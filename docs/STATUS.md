## Open risks and decisions

- **Distribution (decided 2026-09-26): self-distributed unsigned `.xpi` only.** addons.thunderbird.net rejects Experiment-based add-ons outright (the maintainer, confirmed by Daynizer's rejection), and this add-on can't work without an Experiment: Thunderbird 156's official add-on APIs have nothing for chat (checked 2026-09-25). So there's no ATN listing and no signed build. Users install the `.xpi` from file and, like Daynizer, set `xpinstall.signatures.required=false` in the Config Editor. The paid ATN plan in `docs/PLAN.md` is dropped.
- **Selling it:** **Decided 2026-09-26 (the maintainer):** the OMEMO add-on as it stands is released **free** (MPL-2.0, public), in the hope that Thunderbird adopts it, with the README asking for donations through a button to the maintainer's sponsors page (`.github/FUNDING.yml`). A second, paid **Pro** version adds calling (milestone 8) for **$10**. Since the free repo is public, Pro's calling code lives in a separate private repo under the maintainer's own license (MPL-2.0 is per file, so new files can be proprietary; any MPL file Pro changes must have its source offered to Pro's buyers). Plan: generic extension points in the free repo, the calling code in Pro's own files.
- **OTR and OMEMO in the same conversation:** Thunderbird has built-in OTR, which can start on its own between XMPP contacts. Still open: make sure the two never both encrypt a conversation (prefer OMEMO when the peer has OMEMO devices, and keep OTR out of it), and tell the user which one is active. Testing so far runs with OTR off (`chat.otr.enable`=false), since OTR crashed Thunderbird.
- **oldmemo's wire format has no reference** (but a real Cheogram client's oldmemo messages now decrypt, 2026-09-25). Every oldmemo implementation is GPL/AGPL. It gets confirmed against real clients (Conversations, Gajim) in 4.12, where we also save real stanzas as test fixtures. One item to check there: we send `pn` the way libsignal does (last index, not length) and accept either reading on receive.
- **oldmemo key exchanges without a pre key:** libsignal makes `preKeyId` optional, but our protobuf schema requires it. Fine for what we send; relax it if a real client ever omits it (4.12).
- **noble 2.x migration (2.11):** optional. We use 1.x names that also exist in 2.x where it was cheap.
- **The project-root docs are not in git:** `NEXT.md`, `_context.md` and `AGENTS.md` sit outside the repo. Consider moving them in.
